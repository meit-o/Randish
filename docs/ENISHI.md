# ENISHI MVP

既存のSpring Boot 3.5 / Java 21 / JDBCを使い、React 19のWebクライアントを追加しました。ENISHI専用の起動入口・テーブル・ローカルDBを使います。既存Randishの `.env` を読み込まずに起動できます。外部へのデプロイは行っていません。

## 起動

Java 21以降、Maven、Node.jsが必要です。リポジトリのルートで実行します。

```powershell
node scripts/enishi.mjs --demo
```

初回はWeb依存関係の導入、Webビルド、Javaコンパイルを実行します。起動後に http://127.0.0.1:8085/ を開きます。終了はCtrl+Cです。WindowsではJAVA_HOME未設定の場合、標準のJavaインストール先からJDKを探します。見つからない場合はJAVA_HOMEを設定してください。

デモなしで開始する場合：

```powershell
node scripts/enishi.mjs
```

通常用は `server/data/enishi.mv.db`、デモ用は `server/data/enishi-demo.mv.db` に永続化します。再起動してもユーザー、通知、滞在、手紙、同意、チャットは保持されます。

フロントエンドを個別に編集する場合は、APIを起動したうえで `web/` で `npm.cmd run dev`。ViteからAPIへプロキシします。`npm.cmd run build` はSpringの静的ファイル配信先に出力します。RollupはWindowsのネイティブモジュール制限に対応するWebAssembly版です。

## サーバーの判定とプライバシー

`EnishiService` にルールを集約しました。操作と定期判定は、共通ロック行の `SELECT ... FOR UPDATE` を含むトランザクションで実行します。チェックイン中テーブルのユーザー主キー、すれ違いの複合主キー、2人組のマッチ一意制約が重複を防ぎます。チェックアウト時も未記録分を判定します。終了処理は繰り返しても重複しません。

日付をまたぐ重複はJSTの午前0時で分割し、その日の連続5分がある場合だけ記録します。別々の短い滞在を足して5分にすることはありません。すれ違いは滞在だけから判定し、手紙・返信・リアクションの数は参照しません。

他人の現在地・滞在・滞在時刻を返すAPIはありません。位置情報は距離の検証に使用し、取得した座標を保存しません。候補にはプロフィールと3回以上達成した共通施設のみを返します。手紙・返信の他人向け投稿日時もJSTの日付に丸め、匿名投稿から実際のユーザーIDやプロフィールを返しません。匿名投稿者をブロックしても、ブロック管理では匿名表示と解除用の別IDを使います。

片方の同意・見送りでは相手に通知レコードも即時受信イベントも送りません。自分の別タブだけ更新します。双方同意が成立したときに両者を更新します。チャットのSSEには本文を載せず、更新通知後の本文取得時に参加資格を再検証します。解除・ブロック・ログアウト時には既存の対象接続も終了し、その後の閲覧・送信を拒否します。再マッチングは双方の新たな選択で成立し、新しい世代のチャットとして以前の会話を再公開しません。

手紙は7日間、その施設へ現在チェックインしている人が閲覧・返信できます。投稿者は退出・期限終了後も自分の手紙と返信を読めます。退出後・期限終了後の返信とリアクションは投稿者にも許可しません。自分が書いた返信の管理一覧には自分の本文だけを表示し、他人の手紙は返しません。手紙を削除すると返信スレッドも閲覧不可になります。

パスワードは既存のPBKDF2サービスでソルト付きハッシュ化。セッションIDはハッシュ化してDBに保存し、CookieはHttpOnly／SameSite=Strict、7日間有効です。更新リクエストの専用ヘッダーと同一オリジン配信でCSRFを防ぎ、既存の認証用レート制限を適用しています。ユーザー投稿はReactのテキストとして描画します。

## 仮設定と選定理由

| 設定 | 初期値 | 理由 |
| --- | --- | --- |
| ENISHI_CHECKIN_RADIUS_METERS | 150m | 屋内や市街地でのGPSの揺れをある程度許容するため |
| ENISHI_VISIT_HOURS | 4時間 | 読書やカフェでの滞在を想定しつつ、退出忘れによる長時間の記録を抑えるため |
| 判定間隔 | 10秒 | チェックイン中でも5分到達から通常10秒以内に記録するため。API操作時にも判定 |
| 公開期間 | 7日間 | 手紙の公開期間。自己スレッドは期限終了後も保持 |
| 本文・返信 | 各200文字 | 仕様に合わせてサーバーでも制限 |
| チャット | 1000文字／送信 | MVPのテキスト会話として上限を設定 |
| プロフィール | 名前30文字・自己紹介300文字 | 候補画面で読みやすい長さを仮設定。画像は256px角に調整 |
| ENISHI_DEMO_ENABLED | false | サンプル認証・位置情報省略のデモ経路を通常運用で無効にするため |
| ENISHI_SECURE_COOKIE | false | localhostのHTTPで試せるようにするため。本番HTTPSではtrueに設定 |
| ENISHI_PORT | 8085 | 既存アプリの8080番と分けるため |

位置情報は端末の申告値なので、改ざんや偽装を防ぐ証明にはなりません。また、150m以内の別施設や別フロアを区別できません。位置を確認するのはチェックイン時だけで、実際にその後も滞在しているかを追跡しません。有効4時間はこの誤差を抑える上限です。距離と有効時間は、実施設の密度・利用状況を検証して調整する必要があります。

DB接続は `ENISHI_DATABASE_URL`、`ENISHI_DATABASE_USER`、`ENISHI_DATABASE_PASSWORD`、公開アドレスは `ENISHI_SERVER_ADDRESS` で設定できます。PostgreSQL用JDBCドライバーは既存構成にありますが、今回の実DB検証はH2のみです。

## 動作確認

```powershell
node scripts/enishi.mjs --test
```

時刻を固定したH2テストとMockMvcで、次を確認します。

ENISHI用の20件はすべて成功しました。

- 同時操作で複数施設へチェックインできず、同じ施設への再操作で重複しない。
- 4分59秒では成立せず、5分で成立。滞在中とチェックアウトの両方で記録できる。
- 同じ施設・相手・JST日付の重複なし。分離した短い重複は合算しない。
- 深夜前後3分ずつは成立せず、各日5分ずつなら2日分として記録。
- 有効時間で自動終了。距離超過・無効な座標を拒否。
- 同一施設で3回に達して候補化。別施設の回数は合算しない。
- 片方の選択・見送りで相手の通知・候補データ・即時イベントが変化しない。
- 双方同意でチャット利用、第三者アクセス拒否、送信の重複防止。
- 解除・ブロックで既存SSE接続が完了し、以降の取得・送信を403で拒否。
- 再マッチングは双方の再同意を要求し、以前のメッセージは非公開。
- 退出・期限で手紙の閲覧／返信資格が切り替わり、投稿者だけ履歴を保持。
- 投稿削除、返信削除、ブロックによる相互非表示、匿名性、日時の秘匿。
- 通報の保存と管理者以外のアクセス拒否、退会・ログアウトによるセッション失効。
- 実時間が進んでもサンプル会話の世代が一致する。

Webの本番ビルド、1440pxと390pxの画面、サンプルログイン、施設詳細、チェックイン後の手紙閲覧・返信、チャット送信をブラウザーでも確認しました。

既存Randishの全体テストも実施しました。H2にPostgreSQL互換モードがなかったため、既存テストのDB設定をアプリと合わせて修正しました。そのうえで、既存67件中5件には、今回のENISHI追加と独立した既存の不整合が残っています。`RandomHistoryRepository` のSELECTが `actual_spend` を取得しない問題に関連する4件と、`coordinateSearchRetriesPrimaryProviderWithoutDistanceWhenNearbyIsEmpty` の件数差1件です。ENISHIのテストは独立して実行できます。

## 残っている作業・検証範囲

依頼された主要MVPフローは実装済みです。本番公開、実施設情報の精査、メールの本人確認・パスワード再設定、実機GPSの精度検証、PostgreSQL実環境での検証は行っていません。画像はデモ施設のイメージ写真で、実施設の写真ではありません。

DBの共通ロックと全滞在からの集計は、小規模MVP向けです。多数ユーザーに向けた差分集計、履歴保持期間と削除方針、一覧・チャットのページング、運用監視、分散配信、バックアップ、通報対応の運用を整備してから公開してください。モバイルOSのプッシュ通知は実装対象外で、通知はアプリ内です。
